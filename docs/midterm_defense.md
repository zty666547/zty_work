# 9月10日期中答辩方案

## 一句话问题

普通RAG会根据一段不完整错误描述立即生成答案，但真实故障诊断需要主动获取最有价值的信息，并保证修复步骤满足前置条件和安全约束。

## 展示顺序

1. 说明普通问答的局限：信息不完整、原因并存、版本差异、危险建议；
2. 展示故障因果图谱Schema；
3. 输入一条`ModuleNotFoundError`或PyTorch GPU报错；
4. 展示初始候选原因概率；
5. 展示系统选择的问题以及信息增益；
6. 回答两到三次，观察候选原因排序变化；
7. 展示带前置检查、风险和官方来源的排查方案；
8. 展示四种选问策略在30条来源约束案例上的对比结果与离线模式。

## 期中已完成

- 基础因果图谱94个节点、218条关系；合并证据层后共130个节点、338条关系；
- 三个故障族、14个候选原因、14个主动问题；
- 30条`EvidenceChunk`、BM25召回和文本证据—图谱先验融合；
- 信息增益选问、贝叶斯更新和停止策略；
- 检查—修复前置条件与风险验证；
- 离线模板与DeepSeek受控编排双模式；
- Streamlit候选概率、主动问题和诊断子图页面；
- 三个故障族各10条、覆盖全部14个原因的30条诊断路径；
- 不追问、固定顺序、随机追问、信息增益四种可替换策略及统一评测。
- 仅图谱、仅文本、图文融合以及是否主动询问的五组消融实验。
- 原始数据合并、Schema校验、稳定排序、内容指纹和Neo4j写入后核验流程。
- `C1/C2/C3`声明与`E001…`证据双白名单知识注入，未知ID自动回退。

## 当前实验结论

- 混合检索后不追问的Top-1为73.3%，说明文本证据能够改善初始排序；
- 信息增益策略Top-1为100%，平均追问2.80次，3问内成功率66.7%；
- 固定顺序与随机追问的Top-1分别为96.7%和97.5%，平均均需要3.23次；
- 消融中仅文本初始Top-1为76.7%，当前简单融合为73.3%，说明人工先验与固定融合权重仍需校准；
- 图谱主动诊断与混合主动诊断均为100%，混合检索把平均追问从3.10次降至2.80次；
- 30条路径具有来源但仍是合成数据，不能代替真实故障对话评估。

## 诚实边界

- 概率参数是可解释启发式值，尚未用大规模真实故障统计校准；
- 只覆盖三个常见故障族，不是通用运维系统；
- 命令只展示不执行；
- 官方文档能证明检查方法与兼容原则，但不能证明某个具体用户故障的真实根因。
