# 期中答辩方案（9月10日）

## 建议目标

期中不追求所有功能完成，重点证明选题明确、数据真实、技术路线可行、核心检索已经跑通。

## 6页内容

1. **问题与用户**：低年级学生难以快速从培养方案表格中找到课程、学分和学期信息。
2. **项目目标**：构建能自然语言问答、展示证据和版本范围的培养方案助手。
3. **知识图谱 Schema**：展示 6 类实体、6 类关系和“知识工程”局部图。
4. **技术路线**：构建 → 检索 → 证据注入 → 回答，对应课程要求的三个组件。
5. **当前结果**：70 个实体、170 条关系；展示“第四学期有哪些专业核心课”的组合检索结果。
6. **计划与风险**：9月10日前完成核心链路，9月15日前完善界面、评测、演示和报告；说明年级版本与数据完整性边界。

## 现场演示顺序

1. 打开学生端网页，先展示“当前仅支持2023级”的提示。
2. 提问“知识工程是多少学分，建议在哪个学期修读？”
3. 展开证据，解释 Course 属性和 OFFERED_IN 关系。
4. 提问“第六学期有哪些专业选修课？”，解释多条件交集检索。
5. 输入知识库外问题，展示系统拒答而不是编造。

## 老师可能追问

- **为什么不是普通数据库？** 图模型能自然表达课程、学期、类别、开课单位和毕业要求之间的连接，并支持可解释的多条件与多跳检索。
- **大模型在哪里？** 可用于原始文本三元组抽取和检索证据上的答案生成；核心检索不依赖大模型，便于稳定复现。
- **如何降低幻觉？** 只向模型注入检索子图，无证据时拒答，并在界面展示来源和适用年级。
- **为什么默认1跳？** 当前问题是直接课程关系，1跳召回更精确；复杂问题可动态扩展。
- **数据是否完整？** 当前是课程答辩 MVP 的代表性数据，不冒充教务系统；后续按年级导入完整培养方案。
