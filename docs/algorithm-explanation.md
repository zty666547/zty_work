# 主动诊断算法的三步解释

最终说明不需要罗列所有算法组件，只需沿固定案例解释三个动作。

## 1. 初始检索形成候选

用户输入Open WebUI容器无法连接宿主机Ollama后，系统使用固定特征和BM25检索证据，再沿`CHUNK_SUPPORTS_CAUSE`映射到候选原因。当前固定轨迹得到5个候选原因，“服务地址配置错误”为56.0%。

## 2. 选择最值得问的问题

```text
问题效用 = 信息增益 × 可回答率 − 0.02 × 检查成本 − 0.05 × 风险成本
```

第一问“宿主机正常但容器访问失败吗”的信息增益为0.733 bit、可回答率为90%、检查成本为1、风险成本为0，因此效用约为0.640。系统选择效用最高的问题，而不是简单按照固定顺序提问。

## 3. 根据观察更新并稳健停止

用户回答“宿主机成功、容器失败”，对应观察在“服务地址配置错误”成立时出现的条件概率为0.97。系统使用该条件概率进行贝叶斯更新，使该原因从56.0%上升到95.2%，候选分布熵从1.850 bit下降到0.364 bit。

第二次有效回答后，首位原因达到96.9%，且同时满足：

- 首位概率不低于78%；
- 第一名领先第二名不少于20个百分点；
- 至少获得2次有效回答。

系统才停止追问并展开检查、修复、风险和来源。概率用于决定排查顺序，最终原因仍需检查结果确认。

## 实验口径

当前42条已查看案例中，可回答性感知策略改变了15条案例的首问；在原28条开发案例中，Top-1由96.4%变为100%。这些数据只能说明算法在开发集中的行为，不能称为真实世界准确率。

## 知识注入只需简要交代

最终原因确定后，系统从图谱中生成包含检查、修复、风险和来源的结构化方案，并转换为`C1…`声明与`E031…`证据白名单。DeepSeek只能调整声明顺序、选择已召回证据和设置表达侧重，不能新增原因、命令、修复或链接。非法结构会被拒绝并回退到确定性离线答案。

当前9次合法编排全部通过，24次非法结构全部被拒绝。这只验证程序边界，不代表开放式大模型安全性达到100%。
