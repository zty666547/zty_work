# 系统架构说明

## 1. 产品定位

系统定位为面向实际应用的高完成度原型，服务希望快速理解培养方案的低年级学生。当前数据版本是天津大学 2023 级人工智能专业培养方案；界面和答案均显式展示版本范围，防止不同年级规则混用，不声称已达到正式教学系统的部署标准。

## 2. 三个课程要求组件

| 课程要求 | 本项目实现 |
| --- | --- |
| 知识图谱构建 | 结构化录入或 DeepSeek 三元组抽取，经 Schema 校验后写入 Neo4j |
| 检索器 | 别名实体链接、1 跳邻域扩展、多实体交集筛选、属性召回 |
| 大模型 | 将图谱子图注入 Prompt，由 DeepSeek 生成受证据约束的答案 |

系统还提供内存图和离线答案器，让没有 Neo4j 或 API Key 时也能演示检索链路和学生端产品。

## 3. 端到端数据流

```text
课程表/培养目标/毕业要求
          ↓
结构化 JSON 或 LLM 信息抽取
          ↓
实体与关系校验（类型、重复、悬空关系）
          ↓
Neo4j / MemoryGraphClient
          ↓
用户问题 → 别名实体链接 → 1 跳邻域扩展
          ↓
多条件查询：保留同时连接多个查询实体的课程节点
          ↓
图谱证据文本 → 离线答案器或 DeepSeek
          ↓
答案 + 适用年级 + 文档来源 + 可展开证据
```

## 4. Schema 设计

实体包括专业、课程、课程类别、学期、开课单位和毕业要求。核心关系示例：

```text
(2023级人工智能专业)-[:HAS_COURSE]->(知识工程)
(知识工程)-[:BELONGS_TO_CATEGORY]->(专业核心课)
(知识工程)-[:OFFERED_IN]->(第4学期)
(知识工程)-[:TAUGHT_BY]->(智能与计算学部)
```

把学分、课时、课程代码存为课程属性，把学期和类别建成节点，是为了同时支持属性查询和组合条件查询。

## 5. 检索方法

1. 将问题转为小写，与实体名称和别名做确定性匹配。
2. 对命中实体分别扩展 1 跳邻域，得到带节点属性的三元组。
3. 当问题同时命中“第6学期”和“专业选修课”时，优先保留同时连接两个条件的课程，避免召回该学期所有课程。
4. 将去重、排序后的证据转为文本，供答案器使用。

采用 1 跳作为默认值，是因为当前问题主要是课程与学期、类别、单位之间的直接关系。扩大跳数会带来更多无关邻居；未来处理复杂培养路径时可按问题动态选择跳数。

## 6. 知识注入与防幻觉

DeepSeek 的系统提示明确要求只依据检索上下文回答，无证据时返回“根据当前知识图谱无法回答”。学生端额外显示：

- 当前适用范围：2023级人工智能专业；
- 原始依据名称；
- 命中实体和完整图谱证据。

现有培养方案未给出明确先修关系，因此 Schema 和回答均不擅自推断先修课程。

## 7. 可验证性

- 单元测试覆盖数据加载、上下文格式、别名链接、关系属性写入、组合查询和离线答案。
- 检索评测集分别检查“实体是否链接正确”和“答案所需证据是否召回”。
- `scripts/inspect_data.py` 输出实体/关系规模，并在入图前校验数据。
