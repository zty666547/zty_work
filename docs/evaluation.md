# 选问策略对比实验

## 目的

验证两件事：主动获取观察信息是否优于根据初始描述直接猜测；信息增益选问是否能比无策略追问更快缩小原因集合。

## 公平设置

- 四种策略共用同一份因果图谱、8 条冻结诊断路径、贝叶斯更新和停止条件；
- `direct` 不追问，直接输出先验排序；
- `fixed_order` 按知识库顺序提问；
- `random_question` 从剩余问题中随机选择，使用种子 2026 起的 100 次重复实验；
- `information_gain` 选择“期望熵下降－检查成本－风险成本”最高的问题；
- 当前 3 条路径标为开发集、5 条标为测试集。该划分主要用于后续扩充，现有结果不视为独立盲测。

## 指标

| 指标 | 含义 |
| --- | --- |
| Top-1 | 最终排名第一的原因是否为标注首因 |
| MRR | 标注首因排名倒数的平均值，越高越好 |
| 平均追问 | 完成一次诊断所需问题数，越低越好 |
| 3问内成功 | 不超过三问且Top-1正确的路径比例 |
| 平均熵下降 | 追问前后候选原因不确定性的减少量 |

## 当前结果

| 选问策略 | 轨迹数 | Top-1 | MRR | 平均追问 | 3问内成功 | 平均熵下降 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 不追问 | 8 | 37.5% | 0.581 | 0.00 | 37.5% | 0.000 bit |
| 固定顺序 | 8 | 100.0% | 1.000 | 3.00 | 75.0% | 1.281 bit |
| 随机追问 | 800 | 100.0% | 1.000 | 3.22 | 53.2% | 1.343 bit |
| **信息增益** | **8** | **100.0%** | **1.000** | **2.75** | **75.0%** | **1.330 bit** |

在当前小样本上，三种追问方法最终都能找到首因，因此主要差异体现在提问效率：信息增益比固定顺序少 0.25 问，比随机追问少 0.47 问；它与固定顺序的 3 问内成功率相同，尚不能证明在所有效率指标上都占优。

## 复现

```bash
python scripts/evaluate_diagnosis.py
python scripts/evaluate_diagnosis.py --random-runs 100 --seed 2026 \
  --json data/evaluation/baseline_results.json
```

## 局限与下一步

- 8 条路径数量过少，且来自当前知识库设计，结果主要用于验证机制和防止代码回退；
- 下一版应扩充至 24–36 条脱敏案例，先冻结测试集，再调整开发集上的概率参数；
- 应报告各故障族结果和置信区间，避免总体平均掩盖单一场景缺陷；
- 增加版本条件、证据检索和安全验证指标后，再形成最终答辩结论。
