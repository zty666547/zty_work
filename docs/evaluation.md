# 选问策略对比实验

## 目的

验证两件事：主动获取观察信息是否优于根据初始描述直接猜测；信息增益选问是否能比无策略追问更快缩小原因集合。

## 公平设置

- 四种策略共用同一份因果图谱、BM25证据检索、先验融合、30条诊断路径、贝叶斯更新和停止条件；
- `direct` 不追问，直接输出先验排序；
- `fixed_order` 按知识库顺序提问；
- `random_question` 从剩余问题中随机选择，使用种子 2026 起的 100 次重复实验；
- `information_gain` 选择“期望熵下降－检查成本－风险成本”最高的问题；
- 三个故障族各10条，覆盖全部14个候选原因；9条用于开发，21条在本版本起冻结为测试集；
- 每条路径均引用官方文档或公开问题，但报错描述和观察答案是基于来源改写的合成数据，不是真实用户日志。

## 指标

| 指标 | 含义 |
| --- | --- |
| Top-1 | 最终排名第一的原因是否为标注首因 |
| MRR | 标注首因排名倒数的平均值，越高越好 |
| 平均追问 | 完成一次诊断所需问题数，越低越好 |
| 3问内成功 | 不超过三问且Top-1正确的路径比例 |
| 平均熵下降 | 追问前后候选原因不确定性的减少量 |

## 当前结果

| 选问策略 | 轨迹数 | Top-1 | MRR | 平均追问 | 3问内成功 | 平均熵下降 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 不追问 | 30 | 73.3% | 0.861 | 0.00 | 73.3% | 0.000 bit |
| 固定顺序 | 30 | 96.7% | 0.983 | 3.23 | 46.7% | 1.225 bit |
| 随机追问 | 3000 | 97.5% | 0.988 | 3.23 | 49.1% | 1.238 bit |
| **信息增益** | **30** | **100.0%** | **1.000** | **2.80** | **66.7%** | **1.368 bit** |

在全部30条路径上，信息增益比固定顺序和随机追问均少0.43问；3问内成功率分别高20.0和17.6个百分点。仅看21条冻结测试路径，信息增益、固定顺序、随机追问和不追问的Top-1分别为100%、95.2%、96.5%和71.4%。这些数字评估的是“相同混合检索下如何选问”。

## 组件消融实验

为区分文本检索、图谱先验与主动询问的贡献，另设五个配置。它们使用同一知识库和30条路径，只切换证据融合权重与是否追问。表中的“仅BM25文本证据”是指候选排序不使用人工图谱先验；证据片段到候选原因的受控映射仍来自图谱，因此不是脱离知识图谱的自由文本问答。

| 配置 | Top-1 | MRR | 平均追问 | 3问内成功 |
| --- | ---: | ---: | ---: | ---: |
| 仅图谱先验，不追问 | 23.3% | 0.493 | 0.00 | 23.3% |
| 仅BM25文本证据，不追问 | **76.7%** | **0.878** | 0.00 | **76.7%** |
| 图文融合，不追问 | 73.3% | 0.861 | 0.00 | 73.3% |
| 图谱先验＋主动询问 | 100.0% | 1.000 | 3.10 | 63.3% |
| 图文融合＋主动询问 | **100.0%** | **1.000** | **2.80** | **66.7%** |

结果表明：BM25对初始候选排序贡献明显；当前固定权重的简单融合没有超过仅文本检索，暴露出人工图谱先验尚未校准；主动询问能补足初始描述的信息缺失；文本证据加入后保持最终准确率，同时把平均追问减少0.30次。这是当前原型的机制验证，不应解释为真实环境中的准确率承诺。

## 知识注入边界测试

三个故障族分别测试`diagnosis/checks/safety`三种合法编排，共9次；每个故障族再测试未知声明、遗漏声明、重复声明、未召回证据、重复证据、非法侧重点、自由文本和畸形类型，共24次非法编排。

| 指标 | 结果 |
| --- | ---: |
| 合法编排接受率 | 100.0%（9/9） |
| 非法编排拒绝率 | 100.0%（24/24） |
| 误放行率 | 0.0% |
| 误拒绝率 | 0.0% |

该实验验证的是结构化声明—证据白名单的程序边界，不等同于开放式LLM安全评测。由于模型无权直接输出技术内容，非法结构只会触发离线模板回退。

## 局限与下一步

- 当前路径由来源材料和知识库联合构造，结果主要用于验证机制和防止代码回退；
- 下一版应收集独立、脱敏的真实故障对话，只允许在开发集上调整概率参数；
- 需要在独立真实案例上重新验证Text Only、Graph Only和Hybrid结论，并只在开发集上校准融合权重；
- 应报告各故障族结果和置信区间，避免总体平均掩盖单一场景缺陷；
- 在独立案例中增加证据Recall@k、计划覆盖率和端到端响应时间，再形成最终答辩结论。
