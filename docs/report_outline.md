# 最终答辩提纲（9月15日）

## 1. 背景与需求

- 用户：大一至大三、需要理解培养方案的人工智能专业学生。
- 痛点：培养方案表格复杂，跨页查找慢，普通大模型可能混用不同年级规则。
- 目标：自然语言查询 + 图谱证据 + 年级版本范围。

## 2. 数据与知识图谱

- 数据来源与人工核对过程。
- 6 类实体和 6 类关系的设计理由。
- 当前图谱规模与数据边界。
- 演示一门课程的完整邻域。

## 3. Graph RAG 方案

- 实体链接：名称、简称和学期俗称。
- 检索：1跳邻域、属性召回、多条件交集。
- 注入：三元组与属性转为可读上下文。
- 生成：DeepSeek 严格依据证据回答，无证据拒答。

## 4. 系统实现

- 学生端问答页面。
- Neo4j 完整模式与内存图离线模式。
- 数据校验、配置隔离和敏感信息保护。

## 5. 实验结果

- 报告实体链接准确率与证据召回成功率。
- 展示 3 类问题：课程属性、组合条件、知识库外拒答。
- 不把小规模自建评测描述成通用性能结论，明确样本量。

## 6. 创新点与价值

- 从通用电影 Demo 转为本专业真实场景。
- 将年级版本和原始依据作为产品级约束。
- 回答可展开到图谱证据，形成可解释闭环。
- 同一套代码支持无外部服务演示和完整 LLM 链路。

## 7. 局限与后续工作

- 导入2024级、2025级等多版本培养方案，增加版本选择与差异对比。
- 扩充到全部课程，并由教务资料复核。
- 获取可靠依据后增加先修关系和课程—毕业要求支撑矩阵。
- 将字符串实体链接升级为关键词、向量与规则混合检索。
- 增加学生反馈和更大规模评测集。
