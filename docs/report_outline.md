# 期末答辩报告提纲（建议）

> 供你按需填充，形成一份完整的实践报告/PPT 讲稿。

## 一、选题背景与意义
- 为什么需要 RAG（检索增强生成）：缓解大模型幻觉、知识固化、无法实时更新。
- 为什么用**知识图谱**：相比向量检索，图谱能建模多跳关系，检索结果更结构化、更可解释。
- 本项目的定位：以电影领域为例，构建“图谱 + RAG”问答系统。

## 二、系统总体方案
- 端到端流程图（数据 → 抽取 → 图谱 → 检索 → 生成）。
- 技术栈：Neo4j + Python + DeepSeek API。
- 两种抽取模式：结构化直读 / LLM 信息抽取。

## 三、关键技术点（答辩重点）
1. **知识图谱 Schema 设计**：
   - 实体：Person、Movie、Genre。
   - 关系：DIRECTED、ACTED_IN、HAS_GENRE。
2. **基于 LLM 的信息抽取**：
   - 如何用 Prompt + JSON Schema 约束模型输出三元组。
   - 抽取结果的去重与合并策略。
3. **图存储与索引**：
   - MERGE 幂等写入；唯一约束与标签索引。
   - 为什么建索引能提升检索速度。
4. **Graph RAG 检索**：
   - 实体链接（把问题映射到图谱实体）。
   - 邻域扩展（1~N 跳）如何抓住多跳关系。
   - 与纯向量 RAG 的对比（可举例说明）。
5. **生成与防幻觉**：
   - 只允许基于图谱上下文回答；无上下文则明确拒答。

## 四、实验与结果
- 示例问题与回答（最好截图或打印检索上下文）。
  - “诺兰导演了哪些电影？”
  - “莱昂纳多·迪卡普里奥参演过哪些电影？”

## 五、局限与改进方向
- 实体链接依赖字符串匹配，可升级为向量/LLM 实体链接。
- 可扩展多跳/带权关系、动态更新（增量入图）。
- 可引入混合检索（向量 + 图谱）进一步提升召回。
