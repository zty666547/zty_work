# 真实故障案例收集规范

最终实验只接收与现有三个故障族相关、能够确认根因的脱敏案例。公开帖子中只有报错但没有确认原因的记录，可作为待诊断案例，但不得计入准确率。

## 每条案例需要的信息

```text
案例编号：
故障族：Python导入 / PyTorch GPU与CUDA / 服务连接
原始报错或现象：
操作系统与关键版本：
最终确认的根因：
确认根因的检查过程：
哪些问题普通用户可以直接回答：
哪些问题需要运行命令或可能回答“不清楚”：
来源链接或脱敏截图说明：
是否允许计入准确率：是 / 否 / 待确认
```

## 纳入准确率的条件

- 根因由修复结果、维护者回复或可复现检查确认；
- 不包含账号、密钥、真实姓名和个人目录等敏感信息；
- 案例没有参与先验概率、可回答率和停止阈值的调整；
- 同一故障的重复转述只保留一条。

## 数据划分

- 候选池：尚未完成平衡抽样和冻结的公开案例，只用于检查数据流程与发现问题；
- 开发集：只用于调整概率、可回答率和阈值；
- 测试集：参数冻结后运行，不能根据结果反向修改；
- 未确认集：用于展示系统如何继续询问，不计算准确率。

## 当前公开案例种子

`data/evaluation/public_cases.json`收录经过逐条核对的公开Issue，并持续按照第二阶段缺口表扩展。根因可由复现信息确认的案例进入实验候选集；只有故障现象的案例仍保留为未确认数据。未确认案例会被评测脚本自动排除，防止把推测当作标准答案。

截至2026-09-11，候选池含28条确认案例和3条未确认案例，14个候选原因均达到至少2条独立确认记录。这里的来源包括公开项目Issue与能够明确复现“现象—原因—验证方法”的官方排障记录。该候选池已被用于发现模型缺口，因此只能作为后续开发集的抽样来源，不能直接充当最终无偏测试集。

网页诊断结束后，可展开“记录真实排查结果”，选择实际根因并说明是否已由检查或修复确认，然后下载统一格式的脱敏 JSON。密钥、令牌、邮箱、IP 和个人目录会被隐藏；文件只在本地浏览器生成，不会自动上传。即使选择了某个原因，只要没有勾选“已确认”，仍会作为未确认案例保存。

```bash
python scripts/evaluate_public_cases.py
```
