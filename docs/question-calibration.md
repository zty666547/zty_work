# 问题效用参数校准

## 要解决的问题

当前问题节点中的`answerability`和`cost`主要来自人工预估。它们可以用于验证算法机制，但不能表述为真实用户统计结果。

第二版网页会在用户提交观察结果时记录：

- 回答是、否还是“不清楚”；
- 从当前问题显示到提交答案的页面耗时；
- 问题名称和所属诊断案例。

这些数据只随用户主动下载的脱敏案例保存在本地，不会自动上传。

## 校准规则

- 可回答率：将是/否视为有效回答，将“不清楚”视为无法回答，并使用`Beta(1,1)`平滑，避免少量样本得到0%或100%；
- 检查成本：用回答耗时的中位数给出三级建议，30秒以内为1，30至90秒为2，超过90秒为3；
- 风险成本：不能由回答时间推断，继续由安全审查单独标注；
- 每个问题少于5条观测时只报告现状，不生成替换建议；
- 工具只输出建议，不会自动修改图谱或冻结参数。

## 使用方法

完成若干次网页诊断并下载案例后运行：

```bash
python scripts/calibrate_question_utility.py debugpath-case-*.json --output question-calibration.json
```

只有经过人工检查、样本量达标并重新冻结版本后，建议值才能进入下一轮对比实验。冻结测试案例不得用于反向修改参数。
