# DebugPath 第二版开发说明

## 为什么开始第二版

第一版冻结测试的14条案例中，有5条在进入主动诊断前就因固定词串未命中而失败。它们对应的图谱证据其实已经存在，问题在于入口只检查故障名称、别名和示例，没有利用证据检索结果。

## 当前新增：可解释故障族检索

第二版入口并行计算两类信号：

```text
用户故障描述
  ├─ 固定特征匹配：错误码、标准异常名、明确别名
  └─ BM25证据检索：证据片段 → 候选原因 → 所属故障族
                         ↓
                 汇总并输出Top-k故障族
```

当前开发公式为：

```text
故障族得分 = 55% × 固定特征得分 + 45% × 图谱证据得分
```

若没有固定特征命中，仍可完全依靠证据路径给出候选故障族。每个候选项会保留命中特征、证据片段、证据支持的原因和分项得分，因此路由过程可以解释和展示。

## 开发回归结果

| 数据 | 数量 | 故障族Top-1 |
| --- | ---: | ---: |
| 原28条开发案例 | 28 | 100.0% |
| 已查看的首次冻结案例 | 14 | 100.0% |

第二组案例已经被用于发现第一版缺陷，现在只能充当第二版开发反馈。该结果说明新组件修复了已知入口失败，不能证明它对全新数据仍有100%准确率。

## 版本隔离

- 第一版核心引擎、服务、图谱、BM25和参数保持冻结；
- 新入口位于`src/retrieval/issue_router.py`，目前尚未接入正式网页；
- 第二版冻结前，新组件保持可选，不覆盖第一版结果；
- 第二版完成后必须重新收集未见外部测试集。
